# Explainer plan — Email Agent

> **Status.** Written 2026-08-07; revised 2026-08-22 against
> `.claude/work-log/m4-reconciliation.md` after four milestones (M0–M3) landed
> and falsified several lines below. The spine, the method and the design
> direction survived unchanged. What changed: §7 gained a fourth move, the
> unlock gate gained a section of its own, figures 11 and 13 were re-specified,
> and figures 14 and 15 were added. This file is the record of *intent*; the
> shipped page is `email-agent-explainer.html`.

Audience: technical, zero context on this repo. Goal: genuine understanding of
the mechanism, not a feature tour. Method: 3B1B — start from a felt question,
show the naive idea, break it, then show the real design.

## The spine

One question runs the whole piece:

> **Would you give a language model write access to your inbox?**

Every section is a sub-answer. The product is not "AI email triage"; it is
*an apparatus for not trusting the AI*. Once the reader sees that, the odd
parts (a queue, a claim token, an AST parser, a five-line comment about a
10-row default) stop looking like engineering trivia and start looking like
consequences.

The naive answer — "sure, with a confirmation dialog" — is where we start, and
where we break it: the dialog and the Gmail API call are separated by time,
by processes, and by a database. **Everything interesting in this codebase
lives in that gap.**

## Concrete thread

One named email carried end to end, so nothing is abstract:

`m18f3` — *"Your weekly deals from Nordpost"*, unread, from `news@nordpost.example`.

It is fetched, embedded, stored, read by the `junk` action, proposed for
Archive (`removeLabels: ["INBOX"]`), written to `pending_operations` as
`pending`, shown to the user, claimed with a token, sent to Gmail, resolved
`applied`. Every section picks it back up. When a section is about failure,
it is *this* message that fails. Two later beats are available and should be
used: the verifier reading `m18f3`'s *current* labels back out of Gmail, and
`m18f3` being requeued to `pending` when those labels contradict the record.

## Section arc

0. **The gap** (hero). The felt question + the thesis figure: approve → apply
   is not one instant.
1. **What it actually is.** Local, single-user, three packages, no server.
   Short. One map figure. One sentence on the browser unlock gate — there is
   no *account*, but there is now a lock on the door — and one on the `0600`
   inside `0700` file modes, because the refresh token was world-readable
   until 2026-08-22.
2. **Getting the mail.** Why OAuth exists rather than a password (naive:
   store the password; break: it is a key to everything, forever, and cannot
   be scoped or revoked alone). Access vs refresh token. Scope. Then the
   credential router and the branch where it deliberately refuses to fall
   back — and the `""` sentinel that means "gcloud ADC, and nothing else",
   with the cost that carries at approval time.
3. **Storing it.** What an embedding is, built from the naive keyword-search
   failure. Cosine similarity. Then the honest beat: **this repo builds the
   vector space and never searches it** — only k-means walks it, with
   Euclidean distance, which on unit vectors is the same ordering.
4. **Five things the database is not.** Each is a measured fact that
   contradicts an intuition, each cost something real. The 10-row cap is the
   headline. Framed as: *what you'd assume / what was measured / what it did.*
5. **Talking to models.** Two fundamentally different shapes — spawn a CLI as
   a subprocess vs. POST to an HTTP API — and what each shape has to survive.
   Then `tokens.ts`: one column, five executors, five different meanings.
6. **An LLM writes code that runs on your machine.** The arc: chat → the model
   writes a `.action.ts` → saved to `~/.email-agent/actions/` → loaded.
   Naive: `import()` it. Break: **importing is executing**. Denylist →
   defeated in one line. Allowlist over an AST. Then the sharpest idea in the
   piece: *does this syntax bind what it appears to bind at runtime?*
   (`declare const process = "safe"`).
7. **The approval gate** (longest). Built in three moves:
   - naive 1: apply, then show what happened → the user never got to say no;
   - naive 2: show a list, apply on approve → a reject issued while an apply
     is in flight succeeds, is reported as honored, and is then overwritten:
     mail destroyed after the user personally refused it;
   - real (move 3): **claim before mutating**. State machine, claim token,
     chunks of 10 — stated as **per call, never per batch** — and the
     `applying` state the protocol invents;
   - **move 4**, and it follows from move 3 rather than sitting beside it:
     *claiming before mutating is what creates a state only a crash can
     produce, and that state needed its own answer.* Naive: retry (a guess).
     Naive: ask the user (**this shipped**, and breaks quietly — the app is
     asking a question it could answer itself). Real: **check Gmail, resolve
     what the end state settles, requeue what it contradicts, ask only about
     the residual — and never claim the check proves authorship.** The six
     residual reasons as a table; the three time bounds (8s < 10s < 20s, and
     the honest ceiling is **30s**); `approvedVia` and `resolutionEvidence` as
     *a record of who said so is not a proof*; the three limits printed as
     limits;
   - then the double-flag auto-apply escape hatch.
8. **How the browser is kept out.** Its own section, not a subsection: CSRF,
   DNS rebinding, `Host`/`Origin`/`Sec-Fetch-Site` and the code's own
   "speed bump, not the boundary"; then the one-time unlock token, the URL
   fragment (a **defect fixed** — the dev server's request logger echoed the
   live token back to the terminal while it rode in the query string), and the
   sharpest fact on the page: **cookies are scoped by (host, path) and never by
   TCP port**, so the credential is deliberately split across a cookie and
   origin-scoped storage. Close by scoping the claim honestly and naming the
   `.env` foot-gun.
9. **Six stories.** Not a changelog — each is a lesson. Story 5 is the sequel
   to story 4: an adversarial mutation re-check found two live invariants that
   no test held, both documented only in a code comment.
10. **Actually using it.** The real commands — including `unlock`, without
    which the page describes a UI the reader cannot open.
11. **The honest part**, sorted by *kind*: never observed end to end /
    rendered by a test but never seen / not covered / deliberate limitation /
    measured facts with an expiry date.
12. **Glossary.** Everything glossed on first use, collected and scannable.
    Including the **five** unrelated meanings of "token" — OAuth, LLM, claim,
    unlock, and the session/binding pair.

## Visuals — what each must make click

Rule applied throughout: one idea per figure; failure paths drawn as
prominently as happy paths; arrows labelled with verbs.

1. **The gap.** A single timeline: `user clicks Approve` … `Gmail mutates`.
   Between them: process boundary, DB write, network. Makes click: *approval
   is not an instant, it is an interval, and intervals have races.*
2. **The three packages + where the mail lives.** The only whole-system
   picture. Makes click: nothing leaves the machine except two calls —
   Gmail and (optionally) a model provider.
3. **What a refresh token buys.** Two lifetime bars: one consent (once) vs.
   access tokens minted hourly. Makes click: *why the app never sees your
   password and why you can revoke it from Google's side.*
4. **The credential router, with the wall.** Decision tree, three branches;
   the fourth arrow — named-account → ADC fallback — drawn as a wall.
   Makes click: *the refusal is the feature.*
5. **What an embedding is.** Points in a plane, three emails, one query;
   near = similar. Annotated with the honest note that nothing in this repo
   issues that query. Makes click: *meaning becomes geometry* — and *a built
   capability is not a used one.*
6. **The 10-row cap.** 25 queued rows → the query returns 10 → two arrows out:
   "user sees 10 of 25" and "the claim's read-back sees 10 of 25, so Gmail is
   mutated for rows nobody recorded". Makes click: *a silent truncation deep
   in a driver became a correctness bug in a safety mechanism.*
7. **The pinned handle.** Two handles on one table; one commits. The other's
   `query()` returns old rows silently; its `update()` throws. Makes click:
   *the asymmetry* — the dangerous direction is the quiet one.
8. **Two executor shapes.** Subprocess vs HTTP, side by side, each annotated
   with the thing only it has to handle. Makes click: *why there is a strategy
   interface at all.*
9. **Parse, don't import.** Before/after pair. Before: file → module graph →
   top-level code runs. After: file → AST → plain object; the module graph is
   never touched. Makes click: *loading and executing were the same act, and
   now they are not.*
10. **The one-line denylist escape.** `({}).constructor.constructor("return process")()`
    walking past a list of forbidden names. Makes click: *why allowlist.*
11. **The queue state machine.** `pending → applying → applied | failed`, plus
    `pending → rejected`, plus the stranded edges out of `applying`. **Both of
    those edges are machine-traversable as of 2026-08-22**, so label them by
    the *evidence that authorises them* rather than by who traverses them:
    `verified-api` (machine, end-state match), `user-confirmed` (human, on
    their word), requeue-to-`pending` (either source), and the residual arrow
    that leaves the machine's reach entirely.
12. **Claim before mutating.** Two parallel timelines, same race. Without the
    claim: reject succeeds → apply overwrites → mail gone after refusal. With
    it: reject loses, and is told so. Makes click: *the whole product in one
    figure.*
13. **Chunks of 10, and the stranded set.** A 25-row batch, crash mid-chunk-2.
    What is applied, what is stranded, what is untouched. Chunk 2 is
    **unattributable, not unknowable** — the end state is checkable, and the
    next figure checks it. Carry the per-call bound in the caption. Makes
    click: *the thing a crash destroys is authorship, not observability.*
14. **The verification pass.** Stale rows enter from the DB-only gate (zero
    stale rows ⇒ zero Gmail calls, zero output, no clock read); one arrow out
    to `applied (verified-api)`, one to `requeued → pending`, one fanning into
    the six residual reasons; the re-read drawn as a second, shorter read
    hanging **only** off the requeue arrow; and the irreducible gap between
    that re-read and the write drawn explicitly. Makes click: *the honest
    answer to ambiguity is not "ask" and not "guess" — it is "check what is
    checkable, and be precise about the shape of what is left."*
15. **The unlock handshake.** The printed link with the `#` drawn as a wall the
    server can never see past; the exchange returning a cookie **and** a body
    value; the browser writing one to the shared jar and one to origin-scoped
    storage; two later request arrows — one carrying both (200) and one
    carrying only the cookie (401 `binding-required`). Annotate the
    sibling-port attacker beside it, and annotate what the whole thing does
    **not** stop. Makes click: *the credential is deliberately split across two
    stores with different scoping rules, because one of those rules has a hole
    nothing in HTTP can patch.*

Cut if the page runs long: 3 and 8 are the most droppable; 6, 9, 11, 12, 13,
14 and 15 are load-bearing and stay. (All fifteen shipped.)

## Design direction

Identity: **"Docket"** — the visual language of a record held pending a
decision. Not a dashboard, not a landing page; a technical publication with a
custody-chain feel.

- **Color.** Warm-grey neutrals biased slightly toward the accent, so they read
  as chosen rather than defaulted. Light ground `#F3F2EF`, surface `#FFFFFF`,
  ink `#171614`, muted `#6A655D`, rule `#DFDCD5`. Dark ground `#121110`,
  surface `#1A1917`, ink `#EDEAE4`. Accent = **hold ochre** `#9A5B12`
  (light) / `#E3A64A` (dark) — used only for the thing that must not happen
  yet. Semantic pair, kept separate from the accent: applied teal `#1B6B5B` /
  `#54BFA6`, refused/destructive `#A6362B` / `#EF8A80`.
  Explicitly avoiding: the cream+serif+terracotta cluster, the lone acid-green
  pop, purple-blue gradients.
- **Type.** No webfont (CSP blocks CDNs, and inlining a face is not worth the
  bytes here). Three deliberate roles from system stacks:
  *display* — heavy system sans at large size with tight tracking (−0.025em);
  *body* — the same sans at normal weight, 65ch measure;
  *utility* — `ui-monospace` for eyebrows, section numbers, status chips,
  identifiers, code, and figure labels. Mono-as-label (not mono-as-display)
  keeps it a technical publication rather than a terminal pastiche.
- **Layout.** Single ~68ch column; figures break out to ~980px inside their own
  `overflow-x: auto` container; a left gutter carries section numbers on wide
  screens and collapses on narrow. Signature device: a 3px **hold rule** down
  the left of any callout describing something the system deliberately refuses
  to do, and rubber-stamp status chips (uppercase mono, hairline border).
- **Themes.** Token-level: palette on `:root`, redefined under
  `@media (prefers-color-scheme: dark)`, then again under
  `:root[data-theme="dark"]` / `[data-theme="light"]` so the viewer's toggle
  wins in both directions. Components only ever read tokens.
- **Shipped as specified.** Draft 2 quietly used a cool-grey/navy scheme
  instead; the shipped page uses the warm-grey + hold-ochre palette above,
  deliberately. The three-way trichotomy this section now has to render —
  `applied` / `requeued` / `residual`, plus six named residual reasons — is
  exactly what the rubber-stamp chip vocabulary is for.
- **Motion.** Almost none: a hairline underline on link hover, and figures do
  not animate. Restraint is the point for a document about restraint.
  `prefers-reduced-motion` respected.

## Honesty rules for this page

- Say plainly what is deliberate limitation vs. what is unfinished.
- Say plainly what has never been observed end to end (no real Gmail account
  on any machine this has run on — so neither a real Gmail *write* nor a real
  Gmail *read* has ever happened).
- **Keep the two-claim split, and print both sentences in this order:**
  *"rendered populated under jsdom by an automated test"* is now **true** for
  the approval and stranded panels; *"observed populated in a real browser"* is
  still **false**. Merging them would overclaim; dropping the first would
  undersell work that was actually done.
- Say once, plainly, that jsdom is not a browser.
- Print the measured facts' expiry dates too: every LanceDB fact is a fact
  about one version, and so is the Gmail read timeout.
- Where the docs and the code disagree, follow the code and say so. Of the
  three disagreements found while writing the first draft, two were fixed in
  the wave that followed and one — the credential-routing chain — is still
  open. Say that; it is a better ending than the original.
