# Module Card: Core Actions

- purpose: Own email action contracts, discovery, user action source files, action execution, and Gmail operation mapping.
- product/module functionality: Built-in and user-created actions can be listed, loaded, run against emails, persisted as results, and mapped to Gmail write operations that are queued for explicit user approval.
- scope boundaries: Does not own Gmail auth/fetch, DB schema, web UI, or CLI presentation. Calls those modules through exported functions only.
- connected modules/submodules: `agents` for model execution, `db/actions` for result persistence, `gmail/operations` for writes, web `/api/actions*`, CLI `run-action` and `list-actions`.
- allowed change types: Action type contract changes, registry/runner behavior, user action path validation, built-in action additions, operation mapping.
- special operating rules: User action filenames must pass `user-action-paths.ts`. USER ACTION FILES ARE NEVER EXECUTED: `loadUserAction()` and `ActionRegistry`'s `ACTIONS_DIR` pass read the file and call `extractActionData()` (`action-source-guard.ts`), which statically evaluates it and returns the action object without the file entering the module graph. Do not reintroduce `import()` — or the `new Function("p", "return import(p)")` bundler escape hatch — on that path; only `registry.ts`'s built-in directory may import, because those files are in-repo and reviewed. Gmail operations should carry `accountEmail` when derived from stored emails; `applyOperations()` uses operation-level account identity before any batch fallback. APPROVAL GATE: `ActionRunner` must never call `applyOperations()` directly — it enqueues via `approval.ts` and mutations only run through `applyPendingOperationsByIds()` after the user approved them (web approvals panel or CLI prompt/`approvals` command). The one exception is the opt-in `gmail.autoApplyActions` setting, which applies the batch right after enqueueing; it requires `gmail.autoApplyAcknowledged`, enforced in `config/settings.ts`, so never read the toggle without going through `loadSettings()`. `applyOperations()` is barrel-private: `actions/index.ts` must never export it (nor may any public specifier reach it), as defense in depth against a by-name import from any workspace-resolvable context (this is no longer load-bearing for user actions, which do not execute, but is still the cheap loud failure). Only `approval.ts` calls it, via relative import, on claimed rows. A regression test (`barrel-surface.test.ts`) pins this. Generated source is also gated at save time by `assertSafeActionSource()`, called from `saveUserAction()` before anything touches disk, so the model gets a 422 it can act on. Save-time and load-time share ONE traversal — `findActionSourceViolations()` is `analyzeActionSource()` with the extracted values discarded — and they must stay that way; a second, parallel evaluator would drift and the drift would be a bypass. It is an allowlist over the TypeScript AST (`typescript` is a runtime dependency of core for this, and is listed in web's `serverExternalPackages` so it is not bundled): only type-only imports/exports, type declarations, static-data variable statements and `export default` are permitted, so a file that passes contains no construct capable of executing. Keep it AST-based — the original text-scanning version was defeated by `({}).constructor.constructor("return process")()`, which names the Function constructor without spelling it, and the payload hid in a string the scanner had already blanked.
- current stubs/placeholders: None known; user actions are parsed rather than imported, guarded by filename/path validation and the pure-data allowlist.
- irrelevant or incomplete code to remove/rework: Regex metadata extraction may be replaced by a typed manifest, but do not remove it without preserving webpack-safe listing.
- docs that must stay aligned: `CREATE_ACTION_SKILLS.md`, `EDIT_ACTION_SKILLS.md`, web action cards, CLI action commands, `docs/architecture/module-index.md`.
- local validation commands/checks: `npm test -- packages/core/src/actions/*.test.ts`, `npx tsc -p packages/core/tsconfig.json --noEmit`, `npm run check:boundaries`.
