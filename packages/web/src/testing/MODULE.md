# Module Card: Web Component Test Harness

- goal: render React components in a test and assert which branch they took. Everything else in this repo's suite runs under `node --test`; this directory is the vitest half, and it exists because three TODOS.md entries said component rendering was uncovered and two of them stayed open across every wave.
- interface: `renderWithQuery(ui)` (a fresh `QueryClient` per test, retries off), `createTestQueryClient()`, `jsonResponse(body, status)`, and `setup.ts` (jest-dom matchers, explicit RTL `cleanup`, a `fetch` that throws until a test stubs it).
- connections: `../../vitest.config.ts` (runner, jsdom, `.test.tsx`-only include, `enforce: "pre"` alias plugin), `../modules/api/testing/vite-alias-plugin.mjs` and `module-aliases.mjs` (the ONE specifier mapping, shared with the `node --test` resolve hook), `../modules/api/module-aliases.test.ts` and `../modules/api/vitest-resolution.test.tsx` (the two halves that keep vitest, tsx and `packages/web/tsconfig.json` in agreement).
- special operating rules:
  - **Name the file `*.test.tsx`, beside the component.** `vitest.config.ts` includes `.test.tsx` only; `.test.ts` belongs to `node --test`, which will pick a misnamed component test up and fail on its first RTL import. That is deliberate — loud beats silently unrun.
  - **`renderWithQuery`, never bare `render`,** for anything that reaches a `src/hooks/` hook. A shared client leaks the previous test's cache; the default retry policy turns an error-branch assertion into a ~30s timeout.
  - **Stub `globalThis.fetch` per test with `vi.stubGlobal`.** What the server said is the premise of the test; hiding it behind a router makes the interesting half invisible. `setup.ts` installs a throwing `fetch`, so forgetting names itself.
  - **Never drive `apiFetch` into a 401 carrying `unlock-required`/`binding-required`.** It calls `window.location.assign`, and jsdom refuses to let that be redefined (`TypeError: Cannot redefine property: assign`) — measured, not folklore.
  - **Always stub `window.confirm` explicitly, both ways round.** jsdom's is a not-implemented no-op returning `undefined`, so an unstubbed destructive-action test takes the "declined" branch by accident and proves nothing.
  - **Mock `sonner` (`vi.mock` + `vi.hoisted` spies) rather than rendering a `Toaster`.** What is under test is which message the component chose, not how sonner paints it.
  - **`Dialog`'s focus trap cannot be asserted here.** It filters candidates on `el.offsetParent !== null`, and jsdom has no layout, so `offsetParent` is always null — a focus-trap test would pass or fail for reasons unrelated to the trap.
  - **Assert the CHOICE, not the string.** Wording lives in `modules/api/*-contract.ts` with its own tests. Compute what you expect by calling that function. Two layers pinning one string means every copy edit breaks two tests and teaches people to update a test without reading it.
  - **A component test never opens the database.** It stubs `fetch`; there is no LanceDB, no `$HOME` redirect and no core write path involved. Anything that needs real data belongs in the route harness (`modules/api/testing/route-harness.ts`) under core's `useTempHome()`, which is still the only sanctioned way to touch a real database — and which THROWS unless every core import sits in an `await import(...)` below it. Do not import that fixture from a `.test.tsx`.
  - **Mutation-check before you commit.** A component test that cannot fail turns an untested component into one that looks tested, which is worse than nothing and is the exact false confidence three TODOS entries warn about.
