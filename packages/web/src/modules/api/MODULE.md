# Module Card: Web API Contracts

- purpose: Own request validation, request guards, and route-local wire contracts for Next API handlers.
- product/module functionality: Parse and validate JSON bodies before route handlers call core modules.
- scope boundaries: Does not own core business behavior or UI state.
- connected modules/submodules: Next API routes under `app/api`, core Gmail/actions/settings modules, `oauth-state.ts` for the OAuth callback flow, `approvals-contract.ts` (shared with `hooks/use-approvals`), `email-lookup.ts` (batched LanceDB email fetch for the approvals routes), `approval-rows.ts` (row → wire shape, shared by the pending and stranded lists), `action-run-contract.ts` (run-result wording, shared with `app/actions`).
- allowed change types: Request parsers, validation errors, route-adapter-only DTOs.
- special operating rules: State-changing routes must validate input and mutation origin before touching core/file/DB/Gmail modules; `gmail.autoApplyActions` must stay gated on `gmail.autoApplyAcknowledged` in both `mergeSettingsUpdate` and `sanitizeSettingsForResponse` (see `normalizeGmailConfig`), mirroring the core invariant so a client cannot enable unattended Gmail writes by sending the toggle alone; non-local or cross-site browser writes require `EMAIL_AGENT_ALLOW_REMOTE_MUTATIONS=1`, and mutations must additionally carry `Origin` or `Sec-Fetch-Site` (browsers always do; a bare `curl` does not) — but treat all of it as anti-CSRF/anti-rebinding hardening, NOT a boundary, since every input is a caller-controlled header; the boundary is the loopback bind in `packages/web/package.json` and `cli/commands/serve.ts`. EVERY handler under `app/api` must call `mutationGuardResponse` or `readGuardResponse` — `route-guards.test.ts` walks the tree and fails otherwise; the sole exemption is `GET /api/auth/callback` (top-level cross-site redirect from Google, protected by its one-time state cookie), and it is named in that test. `readGuardResponse` deliberately does not require the fetch metadata so the address bar still works. The guards read the `Host` HEADER, never `request.url`: installed Next composes that URL from the server's own configured hostname, so it neither carries the caller's host nor matches the origin the browser is using. `approvals-contract.ts` and `action-run-contract.ts` must stay free of `@email-agent/core` imports — client hooks and pages import them, and web code outside this module may not pull core runtime into the browser bundle. That is why `describeActionRunOutcome` PRINTS the failure strings core already composed (`applyError`, `queueError`) rather than rebuilding them. `sanitizeSettingsForResponse` must keep returning `retention`: it was omitted, so the Settings page could not show that resolved audit rows are deleted on a schedule the user never chose. Both approval lists build their rows through `toApprovalOperations` so the label a user reads before deciding a message's fate cannot differ between the pending and the stranded list. `email-lookup.ts` builds ONE combined predicate with backticked `accountId` (LanceDB folds unquoted identifiers to lowercase, and `.where()` replaces rather than ANDs); email-id request bodies and detail queries must include `accountId`, and an explicitly empty value is valid for legacy/gcloud ADC rows; legacy settings written under a removed shape (e.g. old `notifications`, `ui.theme`, `ui.sidebarCollapsed`, `prompts.priority`, `prompts.clustering` keys) must be normalized/dropped before route handlers persist an update, not passed through; `oauth-state.ts` owns the OAuth CSRF-state cookie — `generateOAuthState`/`setOAuthStateCookie` on auth-url issuance, `isValidOAuthState` (timing-safe compare) on callback, and the redirect URI is derived from the request origin (not hardcoded) so `serve --port N` keeps working.
- current stubs/placeholders: None known; local parsers are intentionally dependency-free to avoid package/lockfile churn.
- irrelevant or incomplete code to remove/rework: None known.
- docs that must stay aligned: Route handlers, module index, README environment variables, API smoke checklist.
- local validation commands/checks: `npm test -- packages/web/src/modules/api/*.test.ts`, `npx tsc -p packages/web/tsconfig.json --noEmit`.
